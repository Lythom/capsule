## How to read this

- **What this file covers.** It lists the vanilla deltas between **1.21.11 and 26.1** only. Each "old" name is the 1.21.11 name, i.e. the state the code is in after the 1.21.2 → 1.21.11 slices are applied (`ResourceLocation` is already `Identifier`, `BakedModel` is already `BlockStateModel`, `RenderType` already uses `RenderPipeline`/`RenderTypes`, the GameTest framework is already the 1.21.5 one, and so on).
- **Locations.** Every location is given in the **current 1.21.1 source**, so a few lines will have moved by the time this slice is applied. Search for the quoted symbol, not the line number.
- **Uncertainty.** "verify" means the primer names the change but not the exact final signature. Check it against the decompiled 26.1 sources (NeoForm/MDG `neoFormRuntime` or Loom's `genSources`) before applying.
- **Repeated 26.2 warning.** 26.2 rewrites client rendering again: `MultiBufferSource` is **removed**, `ShapeRenderer` becomes `ShapeOutlineFeatureRenderer`, `LevelRenderer` is split into `LevelExtractor`, and the GUI is reorganised (26.2 primer §"Too Many Rendering Changes" and §"Feature Rendering: The Takeover"). Every rendering item below is marked **[26.2: changes again]**. For those items, do the 26.1 change only as far as needed to compile, or skip straight to the 26.2 design.

        .and(singletonFields(instance))
        .apply(instance, CapsuleLootEntry::new));

private static String giveCommand(ItemStack stack, HolderLookup.Provider registries) {
    StringBuilder sb = new StringBuilder("/give @p ").append(BuiltInRegistries.ITEM.getKey(stack.getItem()));
    DataComponentPatch patch = stack.getComponentsPatch();
    if (!patch.isEmpty()) {
        RegistryOps<Tag> ops = registries.createSerializationContext(NbtOps.INSTANCE);
        StringJoiner parts = new StringJoiner(",", "[", "]");
        for (Map.Entry<DataComponentType<?>, Optional<?>> e : patch.entrySet()) {
            Identifier key = BuiltInRegistries.DATA_COMPONENT_TYPE.getKey(e.getKey());
            if (e.getValue().isEmpty()) { parts.add("!" + key); continue; }
            @SuppressWarnings("unchecked") DataComponentType<Object> type = (DataComponentType<Object>) e.getKey();
            type.codecOrThrow().encodeStart(ops, e.getValue().get())
                .ifSuccess(tag -> parts.add(key + "=" + tag));   // Tag#toString is SNBT
        }

    }

}

## 7. Serializer Records and Recipe Info — AFFECTED (largest server-side change)

**What changed.**
- `RecipeSerializer` is now a **record** `RecipeSerializer<T>(MapCodec<T> codec, StreamCodec<RegistryFriendlyByteBuf, T> streamCodec)`. You cannot `implements RecipeSerializer` any more.
- Vanilla serializer instances move to `RecipeSerializers`, and each recipe class exposes `MAP_CODEC`, `STREAM_CODEC` and `SERIALIZER`. `RecipeSerializer.register` is removed.
- `ShapedRecipe.Serializer` → `ShapedRecipe.MAP_CODEC`, `STREAM_CODEC`, `SERIALIZER`. Same for `ShapelessRecipe`.
- `CustomRecipe` has a **no-argument** constructor, and `CustomRecipe$Serializer` is removed (it was already `SimpleCraftingRecipeSerializer` in 1.21.1).
- `ShapedRecipe`/`ShapelessRecipe` now extend `NormalCraftingRecipe`. Their constructors take `(Recipe.CommonInfo, CraftingRecipe.CraftingBookInfo, …, ItemStackTemplate result)` instead of `(String group, CraftingBookCategory, …, ItemStack)`. Expected shapes (verify):
  - Shaped: `(CommonInfo, CraftingBookInfo, ShapedRecipePattern, ItemStackTemplate)`
  - Shapeless: `(CommonInfo, CraftingBookInfo, ItemStackTemplate, List<Ingredient>)`
- `Recipe#showNotification()` and `Recipe#group()` are **no longer default**. Classes implementing `Recipe`/`CraftingRecipe` directly must implement them.
- `Recipe$CommonInfo` (show-notification and similar) and `CraftingRecipe$CraftingBookInfo` (category and group) provide codec builders for embedding in a `MapCodec`. The exact helper names are not in the primer: copy the field layout of vanilla `ShapedRecipe.MAP_CODEC` from the 26.1 sources.
