# Capsule port inventory — vanilla changes 26.2 → 26.3

Scope: the NeoForged primer "Minecraft 26.2 -> 26.3" (5844 lines, read in full). It is applied **after** the 26.2 port
described by `docs/port-26.2/PLAN.md` and `docs/port-26.2/inventory/*.md`.

How it was checked: every signature below was checked with `javap` against the real **26.3 client jar** (Mojang
piston-meta, unobfuscated, sha1 `e877b6a0…`) and compared with the **26.2 client jar** used for `26.2.md`. Every vanilla
class Capsule imports (325 imports, plus the 26.2-form classes the port introduces: pipelines, submit nodes,
`GuiGraphicsExtractor`, GameTest registry types, recipe records, `ValueInput`…) was diffed with `javap -p` between the
two jars, with package names normalised so that pure package moves do not hide signature changes. Vanilla data and
asset JSON (recipes, advancements, loot tables, enchantments, tags, item definitions, models, blockstates) were diffed
file by file on samples matching what Capsule ships. The loader hooks the 26.2 form relies on were checked in the
NeoForge 26.3.0.115 universal jar and in Fabric API 0.167.0+26.3 (`fabric-rendering-v1` 27.3.2, `fabric-loot-api-v3`
4.0.10, `fabric-recipe-api-v1` 10.0.13).

Capsule's code is still 1.21.1. Each entry gives the **26.2 form** (what the 26.2 port will have produced, per
`26.2.md` and the other inventories) and the **26.3 form** to end up with. `path:line` points at the 1.21.1 source line

## 2. LWJGL with SDL — `org.lwjgl.glfw` removed, key and mouse codes renumbered [COMPILE] [SILENT]

**What changed (checked with javap):**
- `org.lwjgl.glfw.GLFW` is not on the 26.3 classpath (`lwjgl-glfw` dropped from `26.3.json` libraries). Any
  `import org.lwjgl.glfw.GLFW` fails to compile.
- Key codes are now SDL scancodes. `InputConstants` values changed: `KEY_RETURN` 257 → **40**, `KEY_ESCAPE` 256 →
  **41**, `KEY_NUMPADENTER` → 88, `KEY_E` 69 → 8, `MOUSE_BUTTON_LEFT` 0 → **1** (SDL buttons start at 1).
- `KeyEvent` is now `record KeyEvent(int key, int keycode, int modifiers)` (`scancode` → `keycode`; `key` is the
  physical scancode). `InputWithModifiers#isEscape()` = `input() == 41`, `#isConfirmation()` = `input() == 40 ||
  input() == 88` (bytecode checked; space is **not** a confirmation).
- `MouseButtonInfo(int button, int modifiers)` is unchanged in shape; `button` uses SDL numbering.
- Text input: `EditBox#setFocused(boolean)` calls `Minecraft#onTextInputFocusChange(this, focused)` itself when the box
  is editable; `Gui#setScreen` calls `TextInputManager#stopTextInput()` when the screen closes (bytecode checked).

**Affected:**
- `common/src/main/java/capsule/gui/LabelGui.java:18` (`import org.lwjgl.glfw.GLFW`) and `:72` (26.2 form:
  `event.key() == GLFW.GLFW_KEY_ESCAPE || event.key() == GLFW.GLFW_KEY_ENTER`, see `1.21.6-1.21.10.md` §4.6).
- `common/src/gametest/java/capsule/clientsmoke/Showcase.java:130-131` (26.2 form:
  `new MouseButtonInfo(GLFW.GLFW_MOUSE_BUTTON_LEFT, 0)`).
- `common/src/gametest/java/capsule/clientsmoke/ClientSmokeTest.java:724` (26.2 form:
  `new KeyEvent(key.getDefaultKey().getValue(), 0, 0)`): still compiles and still works, because
  `KeyMapping#matches(KeyEvent)` compares `getValue()` with `event.key()` (checked). Only the meaning of the second
  argument changed (now `keycode`). No change needed.

**Do:**
```java

    super.keyPressed(event);
```


(`com.mojang.blaze3d.platform.InputConstants`, unchanged package.)

`LabelGui` keeps working with SDL text input: `init()` calls `textInput.setFocused(true)` (`LabelGui.java:50`), which now
starts SDL text input, and closing the screen stops it. Check by hand that typing a label still works in the real
client (the smoke test calls `charTyped` directly and does not go through SDL).

## 4. `BindGroupLayouts.MATRICES_PROJECTION` removed; vanilla block pipelines split `SAMPLER0`/`SAMPLER2` [COMPILE]

**What changed (checked with javap and bytecode of `RenderPipelines.<clinit>`):**
- `BindGroupLayouts.MATRICES_PROJECTION` is gone. Its two halves remain: `BindGroupLayouts.PROJECTION` and
  `BindGroupLayouts.DYNAMIC_TRANSFORMS`.
- Vanilla 26.3 `CUTOUT_BLOCK` / `TRANSLUCENT_BLOCK` are built from `GLOBALS`, `FOG`, `SAMPLER0`, `SAMPLER2`,
  `PROJECTION`, `DYNAMIC_TRANSFORMS` + `DefaultVertexFormat.BLOCK` + `QUADS` + `core/block` (vertex and fragment),
  `ALPHA_CUTOUT` 0.5 / 0.1. In 26.2 they used `SAMPLER0_SAMPLER2` + `MATRICES_PROJECTION`.
  `BindGroupLayouts.SAMPLER0_SAMPLER2` still exists, but mirror vanilla.
- `RenderPipeline.Builder`: same methods as 26.2 (`withLocation`, `withVertexShader`, `withFragmentShader`,
  `withShaderDefine(String, float)`, `withBindGroupLayout`, `withVertexBinding`, `withPrimitiveTopology`, `withCull`,
  `withColorTargetState`, `withDepthStencilState`, `build`), plus `withSnippet`, `withPushConstantSize`,
  `withColorTargetStates`. `RenderPipeline.builder(Snippet...)` is unchanged. Bind group layouts are now kept in a set
  (duplicates are still an error).
- `BindGroupLayout.Builder#withSampler` is removed (only matters for a custom layout; Capsule's 26.2 form has none).
- `ColorTargetState(Optional<BlendFunction>, GpuFormat, int)`, `ColorTargetState(BlendFunction)`, `WRITE_NONE`,
  `DepthStencilState(CompareOp, boolean)`: unchanged. Depth is still reversed: `DepthStencilState.DEFAULT` is still
  `GREATER_THAN_OR_EQUAL` (checked).
- `assets/minecraft/shaders/core/block.vsh/.fsh` still exist and still honour `ALPHA_CUTOUT` (read from the jar).
  Capsule ships no shader of its own, so the `#moj_import` → `#include` and `layout(location = …)` changes do not apply.

**Affected:** `common/src/main/java/capsule/client/render/CustomRenderType.java` (26.2 `ghostPipeline(..)` uses
`SAMPLER0_SAMPLER2` and `MATRICES_PROJECTION`).

**Do:** see the full file in §5.

## 5. Order Independent Transparency (OIT) + Feature Phase Changes — blended custom geometry needs OIT pipelines [CRASH]

**What changed (checked in bytecode of `SubmitNodeCollection`, `RenderTypeFeatureRenderer`, `PreparedRenderType`):**
- `SubmitNodeCollection#submitCustomGeometry(PoseStack, RenderType, CustomGeometryRenderer)` still routes by
  `RenderType#hasBlending()`: no blending → `solid`, blending → `translucentCustomGeometry`.
- New in 26.3: when **Improved Transparency** is on (`Options#improvedTransparency()`, default `false`, but toggled by
  players, the graphics presets and the `key.debug.improvedTransparency` debug key), the `SubmitNodeCollection` is
  built with `translucentCustomGeometry`, `shapeOutlines`, `afterTerrain`, `translucentBlocksAndItems`, … all aliased
  to one `oitTranslucent` phase. That phase is drawn three times (`OitStage.DEPTH_BOUNDS`, `TRANSMITTANCE`,
  `ACCUMULATE`), and each draw calls `PreparedRenderType#drawFromBufferOit(info, stage, pass)`, which throws
  `IllegalStateException("Render type <name> does not have OIT pipelines set up.")` when the render type was built
  without `RenderSetup.RenderSetupBuilder#setOitPipelines(OitPipelineSet)`.
- `submitShapeOutline(PoseStack, VoxelShape, RenderType, int argb, float width, boolean afterTranslucentTerrain)`
  (signature unchanged) now sends **opaque outlines (`ARGB.alpha(color) == 255`) to the `solid` phase**; only outlines
  with alpha < 255 go to `afterTerrain` / `shapeOutlines`, i.e. to `oitTranslucent` when OIT is on.
- Vanilla render types and their OIT support in 26.3 (bytecode of `RenderTypes.<clinit>`):
  - `RenderTypes.lines()`: opaque, **no** OIT set (fine: alpha 255 goes to `solid`);
  - `RenderTypes.linesTranslucent()`: **no** OIT set, and its pipeline now uses `DepthStencilState.DEFAULT` (writes depth);
  - new `RenderTypes.linesTranslucentNoDepthWrite()` and `linesDepthBias()`: have `RenderPipelines.OIT_LINES_TRANSLUCENT`;
  - `RenderTypes.debugQuads()`: has `RenderPipelines.OIT_DEBUG_QUADS`.
- New public `RenderPipelines.OIT_TRANSLUCENT_BLOCK` (`net.minecraft.client.renderer.oit.OitPipelineSet`): the OIT
  version of vanilla's translucent block pipeline (`core/block`, `ALPHA_CUTOUT` 0.1, `SAMPLER2` added in the accumulate
  stage). `OitPipelineSet.builder(String, RenderPipeline.Builder)` exists to build one's own.
- NeoForge 26.3: `RegisterRenderPipelinesEvent#registerPipeline(RenderPipeline)` is unchanged; it gains
  `registerOitPipelineSet(OitPipelineSet)` and `registerOptionalPipeline(RenderPipeline)`.

**Affected (everything blended that Capsule submits):**
- The ghost colour pass `CustomRenderType.GHOST` (blended), submitted by
  `common/src/main/java/capsule/client/render/CapsuleTemplateRenderer.java:82-111` (`renderTemplate`), reached from
  `CapsulePreviewHandler` (full preview, #88) and `common/src/main/java/capsule/client/CaptureAnimation.java:118`
  (capture animation, #106). **Crash** on the first preview frame with Improved Transparency on.
  `GHOST_DEPTH` has no blending: it stays in `solid`, fine.
- The recall box `common/src/main/java/capsule/client/CapsulePreviewHandler.java:411-427` (`renderRecallBox`, main box
  alpha 200/255, slices alpha `0.01 + i * 0.05`), also called from `common/src/main/java/capsule/blocks/CaptureBER.java:39`.
  The 26.2 form (`26.2.md` §5) uses `RenderTypes.linesTranslucent()` for alpha < 1: **crash** with OIT on, and with OIT
  off it now writes depth.
- Opaque boxes (red error boxes `CapsulePreviewHandler.java:289-291`, wireframe box `:308`, capture-animation box
  `CaptureAnimation.java:122`, all alpha 1 with `RenderTypes.lines()`): no crash; they now draw in the solid phase.
- The linked-inventory cube (`CapsulePreviewHandler.java:358-368`, `RenderTypes.debugQuads()`): fine, has an OIT set.

**Do: 26.3 form of `CustomRenderType`** (replaces the 26.2 form of `26.2.md` §7; only the imports, the layouts and

```java
import com.mojang.blaze3d.systems.RenderSystem;
import com.mojang.blaze3d.vertex.DefaultVertexFormat;
import com.mojang.renderpearl.api.GpuFormat;
import com.mojang.renderpearl.api.pipeline.BlendFunction;
import com.mojang.renderpearl.api.pipeline.ColorTargetState;
import com.mojang.renderpearl.api.pipeline.CompareOp;
import com.mojang.renderpearl.api.pipeline.DepthStencilState;
import com.mojang.renderpearl.api.pipeline.PrimitiveTopology;
import com.mojang.renderpearl.api.pipeline.RenderPipeline;
import com.mojang.renderpearl.api.textures.AddressMode;
import com.mojang.renderpearl.api.textures.FilterMode;
import net.minecraft.client.renderer.BindGroupLayouts;
import net.minecraft.client.renderer.RenderPipelines;
import net.minecraft.client.renderer.oit.OitPipelineSet;
import net.minecraft.client.renderer.rendertype.LayeringTransform;
import net.minecraft.client.renderer.rendertype.RenderSetup;
import net.minecraft.client.renderer.rendertype.RenderType;
import net.minecraft.client.renderer.texture.TextureAtlas;
import net.minecraft.resources.Identifier;

import javax.annotation.Nullable;
import java.util.Optional;

/** Ghost blocks: GHOST_DEPTH keeps the nearest ghost surface per pixel, GHOST then blends only that surface. */
public final class CustomRenderType {
    private CustomRenderType() {}

    private static RenderPipeline.Builder ghostPipeline(String path) {
        return RenderPipeline.builder()
                .withLocation(Identifier.fromNamespaceAndPath("capsule", "pipeline/" + path))
                .withVertexShader("core/block")
                .withFragmentShader("core/block")
                // same layouts, in the same order, as vanilla 26.3 CUTOUT_BLOCK / TRANSLUCENT_BLOCK
                .withBindGroupLayout(BindGroupLayouts.GLOBALS)
                .withBindGroupLayout(BindGroupLayouts.FOG)
                .withBindGroupLayout(BindGroupLayouts.SAMPLER0)
                .withBindGroupLayout(BindGroupLayouts.SAMPLER2)
                .withBindGroupLayout(BindGroupLayouts.PROJECTION)
                .withBindGroupLayout(BindGroupLayouts.DYNAMIC_TRANSFORMS)
                .withVertexBinding(0, DefaultVertexFormat.BLOCK)
                .withPrimitiveTopology(PrimitiveTopology.QUADS)
                .withCull(false);
    }

    public static final RenderPipeline GHOST_DEPTH_PIPELINE = ghostPipeline("ghost_depth")
            .withShaderDefine("ALPHA_CUTOUT", 0.5f)
            .withColorTargetState(new ColorTargetState(Optional.empty(), GpuFormat.RGBA8_UNORM, ColorTargetState.WRITE_NONE))
            .withDepthStencilState(new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, true))
            .build();

    public static final RenderPipeline GHOST_PIPELINE = ghostPipeline("ghost")
            .withShaderDefine("ALPHA_CUTOUT", 0.1f)
            .withColorTargetState(new ColorTargetState(BlendFunction.TRANSLUCENT))
            .withDepthStencilState(new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, false))
            .build();

    private static RenderSetup ghostSetup(RenderPipeline pipeline, @Nullable OitPipelineSet oit) {
        RenderSetup.RenderSetupBuilder builder = RenderSetup.builder(pipeline)
                .useLightmap()
                .withTexture("Sampler0", TextureAtlas.LOCATION_BLOCKS, () -> RenderSystem.getSamplerCache()
                        .getSampler(AddressMode.CLAMP_TO_EDGE, AddressMode.CLAMP_TO_EDGE, FilterMode.LINEAR, FilterMode.NEAREST, true))
                .setLayeringTransform(LayeringTransform.VIEW_OFFSET_Z_LAYERING);
        if (oit != null) builder.setOitPipelines(oit);   // required for any blended type when Improved Transparency is on
        return builder.createRenderSetup();
    }

    public static final RenderType GHOST_DEPTH = RenderType.create("capsule:ghost_depth", ghostSetup(GHOST_DEPTH_PIPELINE, null));
    // vanilla's OIT translucent-block set: same shader, vertex format, textures and alpha cutout as GHOST_PIPELINE
    public static final RenderType GHOST = RenderType.create("capsule:ghost", ghostSetup(GHOST_PIPELINE, RenderPipelines.OIT_TRANSLUCENT_BLOCK));
}
```
