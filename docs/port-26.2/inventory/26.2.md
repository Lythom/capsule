# Capsule port inventory — vanilla changes 26.1 → 26.2

Scope: NeoForged primer "Minecraft 26.1.x -> 26.2" (2640 lines, read in full), the Fabric 26.2 blog post
(fabricmc.net/2026/06/15/262.html), the Fabric 26.2 docs (porting page plus the 26.2 pages "Rendering in the World",
"Block Entity Renderers", "Custom Screens" and "Basic Rendering Concepts").

How it was checked: every signature below was checked with `javap` against the real **26.2 client jar** and the
**26.1.2 client jar** from Mojang's piston-meta. Both jars are unobfuscated, so the names are the Mojang names. I also
checked the NeoForge 26.2.0.95 universal jar and Fabric API 0.161.0+26.2 (fabric-rendering-v1 25.3.3) for the loader
hooks the new rendering needs. I diffed every vanilla class Capsule imports between 26.1.2 and 26.2.

Capsule's code is still 1.21.1. Each entry gives the **26.1 form** (what the earlier port steps will have produced)
and the **26.2 form** to end up with. `path:line` points at the 1.21.1 source line that will become the affected
26.x code.

Version facts for 26.2:
- Java 25 (`java_version: 25` in version.json).
- Fabric: Loom 1.17, Gradle 9.5.1, Fabric Loader >= 0.19.3, Fabric API `0.161.0+26.2`.
- NeoForge `26.2.0.95`.
- Pack formats: resource **88.0**, data **107.1** (26.1.2 was resource 84.0, data 101.1).
- World/data version 4903, protocol 776.

## 1. Pack Changes — pack format numbers

**What changed:** the 26.2 pack versions are resource `88` (minor 0) and data `107` (minor 1). Vanilla 26.2 built-in
packs use the `min_format`/`max_format` style (for example `"min_format": [107, 1], "max_format": 107`).
`pack_format` and `supported_formats` are legacy. The `min_format`/`max_format` style itself was introduced in an
earlier version; the 26.2 part is the numbers.

**Affected:** `common/src/main/resources/pack.mcmeta:3-7` (`"pack_format": 34`, `supported_formats 34..48`).

**Do:** Capsule ships assets and data in one pack, so the range must cover resource 88 and data 107.1. Write:
```json
{
  "pack": {
    "description": "Resources used for Capsule mod",
    "min_format": 88,
    "max_format": 107
  }
}
```
Loader metadata also needs the 26.2 targets. Those are not vanilla changes, but they are listed here so they are not
forgotten:
- `neoforge/src/main/resources/META-INF/neoforge.mods.toml:22` (neoforge range) and `:29` (minecraft range): make
  them `[26.2,26.3)`.
- `fabric/src/main/resources/fabric.mod.json:40-42`: `"fabricloader": ">=0.19.3"`, `"minecraft": "~26.2"`,
  `"java": ">=25"`.
- `fabric/src/main/resources/capsule.mixins.json:5`: `"compatibilityLevel": "JAVA_25"`.
- `gradle.properties`: `minecraft_version=26.2`, `neo_version=26.2.0.95`, `fabric_api_version=0.161.0+26.2`.

## 3. Feature Rendering: The Takeover — `MultiBufferSource` and `Minecraft#renderBuffers()` removed

**What changed:**
- `net.minecraft.client.renderer.MultiBufferSource` (and `$BufferSource`, `immediate(..)`, `immediateWithBuffers(..)`,
  `getBuffer(RenderType)`, `endBatch(..)`) is **gone**.
- `Minecraft#renderBuffers()` is gone. `GameRenderer#renderBuffers()` now returns `RenderBuffers`, and that class
  only has `fixedBufferPack()`, `sectionBufferPool()`, `stagedVertexBuffer()` and `endFrame()`. It has no
  `bufferSource()`.
- `RenderType#draw(MeshData)` and `RenderType#bufferSize()` are removed. `RenderType#mode()` is now
  `RenderType#primitiveTopology()`. There is a new `RenderType#prepare()` that returns a `PreparedRenderType`.
- `OutlineBufferSource` is removed. `FeatureRenderDispatcher` was reworked: `prepareFrame(SubmitNodeStorage)`,
  `renderAllFeatures(SubmitNodeStorage)`, `$PreparedFrame.executeSolid/executeTranslucent/...`.
- World geometry from mods is now drawn either:
  - **(A, preferred)** by *submitting* to a `SubmitNodeCollector`, or
  - **(B)** by drawing yourself through `StagedVertexBuffer` + `PreparedRenderType#drawFromBuffer`.

Unchanged between 26.1 and 26.2 (verified):
- `OrderedSubmitNodeCollector#submitCustomGeometry(PoseStack, RenderType, SubmitNodeCollector.CustomGeometryRenderer)`,
  where `CustomGeometryRenderer` is `void render(PoseStack.Pose, VertexConsumer)`.
- `SubmitNodeCollector#order(int)`.

**Routing (from bytecode of `SubmitNodeCollection#submitCustomGeometry`):**
- a `RenderType` with `hasBlending()==false` goes to the `solid` phase;
- a blended one goes to `translucentCustomGeometry`;
- `executeSolid` runs before `executeTranslucent`.

So a non-blended depth pass is always drawn before a blended color pass. That is exactly the GHOST_DEPTH-then-GHOST
order that Capsule relies on.

**Where to get a collector in 26.2 (loader hooks, verified in the 26.2 jars):**
- Fabric: `LevelRenderEvents.COLLECT_SUBMITS.register(ctx -> ...)`
  (`net.fabricmc.fabric.api.client.rendering.v1.level`). `ctx.submitNodeCollector()`, `ctx.poseStack()`,
  `ctx.levelState().cameraRenderState.pos` (camera `Vec3`), `ctx.levelRenderer()`, `ctx.gameRenderer()`.
  `LevelRenderEvents.AFTER_TRANSLUCENT_TERRAIN` also exists, with the same `LevelRenderContext`, for direct draws
  (path B).
- NeoForge: `SubmitCustomGeometryEvent` on `NeoForge.EVENT_BUS`. It provides `getSubmitNodeCollector()`,
  `getPoseStack()` and `getLevelRenderState()` (camera: `getLevelRenderState().cameraRenderState.pos`).
  `RenderLevelStageEvent.AfterTranslucentBlocks` (still has `getLevelRenderer()`, `getPoseStack()`,
  `getModelViewMatrix()`) is for path B.

**Affected locations (every `MultiBufferSource` / `renderBuffers()` / `getBuffer` / `endBatch`):**

  - `:306-309` wireframe box;

- `common/src/main/java/capsule/client/render/CapsuleTemplateRenderer.java`:

Quads such as the linked-inventory cube (`:358-368`) use the standard `submitCustomGeometry` pattern:
```java
poseStack.pushPose();
poseStack.translate(-camera.x, -camera.y, -camera.z);
collector.submitCustomGeometry(poseStack, RenderTypes.debugQuads(),
        (pose, vc) -> RendererUtils.drawCube(pose, location, 0.01f, vc, 91, 156, 255, 80));
poseStack.popPose();
```
`submitCustomGeometry` copies `poseStack.last()` at submit time. The callback receives that `PoseStack.Pose`, so
change `RendererUtils.drawCube/drawQuad/drawPlane*` to take a `PoseStack.Pose` instead of a `PoseStack`. The vertex
calls are unchanged: `vc.addVertex(pose, x, y, z).setColor(r, g, b, a).setNormal(pose, nx, ny, nz)`.

Line boxes: see §5 (`submitShapeOutline`). The ghost template: see §4 and §8.

**Do (path B, only if a direct draw is kept).** This replaces `MultiBufferSource.immediateWithBuffers` +
`endBatch()`:
```java
private static final StagedVertexBuffer STAGED =
        new StagedVertexBuffer(() -> "Capsule ghost preview", RenderType.BIG_BUFFER_SIZE);

// per frame, inside RenderLevelStageEvent.AfterTranslucentBlocks / LevelRenderEvents.AFTER_TRANSLUCENT_TERRAIN:
PreparedRenderType depthType = CustomRenderType.GHOST_DEPTH.prepare();
StagedVertexBuffer.Draw depthDraw = STAGED.appendDraw(CustomRenderType.GHOST_DEPTH.format(),
        CustomRenderType.GHOST_DEPTH.primitiveTopology());
VertexConsumer depth = STAGED.getVertexBuilder(depthDraw);
// ... write ALL depth-pass vertices ...
PreparedRenderType colorType = CustomRenderType.GHOST.prepare();
StagedVertexBuffer.Draw colorDraw = STAGED.appendDraw(CustomRenderType.GHOST.format(),
        CustomRenderType.GHOST.primitiveTopology());
VertexConsumer color = new TranslucentVertexConsumer(STAGED.getVertexBuilder(colorDraw), alpha);
// ... write ALL color-pass vertices ...
STAGED.upload();                      // no appendDraw allowed after this ("Cannot append draw after upload")
StagedVertexBuffer.ExecuteInfo d = STAGED.getExecuteInfo(depthDraw);
if (d != null) depthType.drawFromBuffer(d);
StagedVertexBuffer.ExecuteInfo c = STAGED.getExecuteInfo(colorDraw);
if (c != null) colorType.drawFromBuffer(c);
STAGED.endFrame();
```
Rules for path B:
- only one vertex builder is live at a time (`getVertexBuilder` finishes the previous one), so never interleave writes
  between two draws;
- pass a `VertexSorting` (`RenderSystem.getProjectionType().vertexSorting()`) to the 3-argument `appendDraw` only
  for a type with `sortOnUpload()`;
- close `STAGED` when the game renderer closes, if you care about the leak.

## 4. `VertexMultiConsumer` removed

**What changed:** `com.mojang.blaze3d.vertex.VertexMultiConsumer` (`create(..)`, `$Double`, `$Multiple`) is deleted in
26.2. It still exists in 26.1.2.

**Affected:** `common/src/main/java/capsule/client/render/CapsuleTemplateRenderer.java:9` (import) and `:84-86`
(`VertexMultiConsumer.create(depthBuffer, new TranslucentVertexConsumer(colorBuffer, alpha))`).

**Do:** stop writing both passes at once. With path A, submit the template twice. The tessellation runs inside each
callback:
```java
public void renderTemplate(SubmitNodeCollector collector, PoseStack poseStack, float alpha) {
    collector.submitCustomGeometry(poseStack, CustomRenderType.GHOST_DEPTH, (pose, vc) -> tesselate(pose, vc));
    collector.submitCustomGeometry(poseStack, CustomRenderType.GHOST,
            (pose, vc) -> tesselate(pose, new TranslucentVertexConsumer(vc, alpha)));
}
private void tesselate(PoseStack.Pose base, VertexConsumer vc) {
    PoseStack ps = new PoseStack();
    ps.last().set(base);
    for (Map.Entry<BlockPos, BlockState> e : templateWorld.entrySet()) {
        ps.pushPose();
        ps.translate(e.getKey().getX(), e.getKey().getY(), e.getKey().getZ());
        // existing per-block body (Services.client().tesselate..., renderFluid(ps, ...)) writing into vc
        ps.popPose();
    }
}
```
The depth type has no blending, so it lands in the solid phase. The color type has blending, so it lands in
translucentCustomGeometry. Ordering is therefore guaranteed (§3).

With path B, write the depth draw completely, then the color draw (see the §3 snippet).

If a combined consumer is still wanted anywhere else, write a 10-line `record PairVertexConsumer(VertexConsumer a,
VertexConsumer b) implements VertexConsumer`. It delegates the 8 abstract methods, which are unchanged in 26.2:
- `addVertex(float, float, float)`
- `setColor(int, int, int, int)`
- `setColor(int)`
- `setUv(float, float)`
- `setUv1(int, int)`
- `setUv2(int, int)`
- `setNormal(float, float, float)`
- `setLineWidth(float)`

This only works with path B's builders if they are not `StagedVertexBuffer` builders live at the same time, so prefer
the two-pass form.

`TranslucentVertexConsumer` (`common/src/main/java/capsule/client/render/TranslucentVertexConsumer.java`) needs **no
26.2 change**: `VertexConsumer` is identical between 26.1.2 and 26.2. It must already override the 26.1 abstract set
(`setColor(int)`, `setLineWidth(float)`), which is an earlier-version item.

## 5. Shape Outlines Feature — `ShapeRenderer` removed

**What changed:**
- `net.minecraft.client.renderer.ShapeRenderer` is gone. In 26.1 its only method was
  `renderShape(PoseStack, VertexConsumer, VoxelShape, double, double, double, int color, float width)`.
- Replacement: `OrderedSubmitNodeCollector#submitShapeOutline(PoseStack poseStack, VoxelShape shape, RenderType
  renderType, int argbColor, float lineWidth, boolean afterTranslucentTerrain)`.
  - `true` → the `afterTerrain` phase;
  - `false` → the `shapeOutlines` phase (verified in `SubmitNodeCollection`).
  - Vanilla block outlines call it with `RenderTypes.lines()` / `secondaryBlockOutline()` and
    `ARGB.colorFromFloat(a, r, g, b)`.
- `Gizmos` (`Gizmos.cuboid(AABB, GizmoStyle)`, `line(..)`) are unchanged from 26.1. Only their renderer moved
  (`GizmoFeatureRenderer`).

**Affected:** every line box (1.21.1 `LevelRenderer.renderLineBox`; in 26.1 either hand-written line vertices,
`ShapeRenderer.renderShape` or Gizmos):
- `common/src/main/java/capsule/client/CapsulePreviewHandler.java`:
  - `:289-291`: error boxes, red `0.8,0,0,1`, ×3 inflate/deflate;
  - `:308`: wireframe `dest` box;
  - `:416`, `:422-425`: `renderRecallBox`, main box plus 5 animated slices with alpha `0.01 + i * 0.05`.
- `common/src/main/java/capsule/client/CaptureAnimation.java:122`: shrinking box, `0.87f` grey.
- `common/src/main/java/capsule/blocks/CaptureBER.java:178-179`: `renderRecallBox` from the BER.

**Do:** replace each line box with a shape outline submit:
```java
// AABB in the current pose space (same coordinates that were passed to renderLineBox)
collector.submitShapeOutline(poseStack, Shapes.create(box), RenderTypes.lines(),
        ARGB.colorFromFloat(a, r, g, b), 2.0f /* line width */, false);
```
- For alpha < 1 (the recall slices) use `RenderTypes.linesTranslucent()`.
- Change `renderRecallBox(PoseStack, int color, AABB, VertexConsumer, double time)` to
  `renderRecallBox(OrderedSubmitNodeCollector collector, PoseStack poseStack, int color, AABB box, double time)`
  and make it call `submitShapeOutline` six times.
- In `CaptureBER.submit(state, poseStack, collector, cameraState)` call
  `CapsulePreviewHandler.renderRecallBox(collector, poseStack, state.color, state.box, state.time)`. Those values are
  extracted into the render state in `extractRenderState`.
- The old `RenderSystem.lineWidth(..)` calls (`CapsulePreviewHandler.java:276`, `:301`;
  `RendererUtils.java:324`, `:328`) become the `lineWidth` argument.

If the 26.1 port already uses Gizmos for these boxes, nothing changes in 26.2.

## 7. Rewriting Vertex Formats / Bind Group Layouts / Blend Factors / GPU Formats / Multiple Color Target States — custom pipelines

**What changed (verified on `RenderPipeline$Builder`, `ColorTargetState`, `BlendFunction`, `RenderSetup`):**
- `VertexFormat.Mode` → `com.mojang.blaze3d.PrimitiveTopology`
  (`QUADS`, `LINES`, `DEBUG_LINES`, `TRIANGLES`, ...).
- `VertexFormat.IndexType` → `com.mojang.blaze3d.IndexType`.
- `BufferBuilder(ByteBufferBuilder, Mode, VertexFormat)` → `BufferBuilder(ByteBufferBuilder, PrimitiveTopology,
  VertexFormat)`.
- `RenderSystem.getSequentialBuffer(Mode)` → `(PrimitiveTopology)`.
- `RenderPipeline.Builder` builder methods:
  - `withVertexFormat(VertexFormat, VertexFormat.Mode)` → `withVertexBinding(0, VertexFormat)` +
    `withPrimitiveTopology(PrimitiveTopology)`;
  - `withUniform(String, UniformType)` / `withSampler(String)` → `withBindGroupLayout(BindGroupLayout)`, using the
    vanilla layouts in `net.minecraft.client.renderer.BindGroupLayouts`: `GLOBALS`, `FOG`, `MATRICES_PROJECTION`
    (= `DynamicTransforms` + `Projection`), `SAMPLER0_SAMPLER2`, `PROJECTION`, `DYNAMIC_TRANSFORMS`, `LIGHTING`, ...;
    or a custom layout via `BindGroupLayout.builder().withSampler("X").withUniform("Y", UniformType.UNIFORM_BUFFER)
    .build()`. No duplicate sampler/uniform names may appear across the layouts of one pipeline.
  - `withColorTargetState(ColorTargetState)` still exists (index 0); `withColorTargetState(int, ColorTargetState)`
    is new.
- `RenderPipeline` getters:
  - `getVertexFormat()` → `getVertexFormatBinding(int)`;
  - `getVertexFormatMode()` → `getPrimitiveTopology()`;
  - `getSamplers()` / `getUniforms()` → `getBindGroupLayouts()`.
- Snippets:
  - `RenderPipelines.MATRICES_PROJECTION_SNIPPET` / `FOG_SNIPPET` are gone (replaced by `BindGroupLayouts`);
  - the vanilla `*_SNIPPET`s are **private** (`BLOCK_SNIPPET`, `GENERIC_BLOCKS_SNIPPET`, `GLOBALS_SNIPPET`, ...);
  - only `POST_PROCESSING_SNIPPET` and `ANIMATE_SPRITE_SNIPPET` are public;
  - neither the NeoForge 26.2 AT nor fabric-rendering-v1's class tweaker opens them;
  - so build Capsule's pipelines from `RenderPipeline.builder()` with explicit layouts.
- Blending:
  - `SourceFactor` + `DestFactor` → `com.mojang.blaze3d.platform.BlendFactor`, with a new `BlendOp`;
  - `BlendFunction(BlendFactor, BlendFactor[, BlendOp])`, `BlendFunction(BlendEquation[, BlendEquation])`;
  - the constants `BlendFunction.TRANSLUCENT`, `ADDITIVE`, `LIGHTNING`, `GLINT`, `OVERLAY`, ... still exist.
- `ColorTargetState(Optional<BlendFunction>, int writeMask)` → `ColorTargetState(Optional<BlendFunction>,
  com.mojang.blaze3d.GpuFormat, int writeMask)`. The main target format is `GpuFormat.RGBA8_UNORM`, which is what
  `ColorTargetState(BlendFunction)` and `DEFAULT` use. Write mask constants: `WRITE_ALL` (15), `WRITE_COLOR`,
  `WRITE_NONE`, ...
- `TextureFormat` → `GpuFormat` (`RGBA8` → `RGBA8_UNORM`, `RED8` → `R8_UNORM`, `DEPTH32` → `D32_FLOAT`).
- `RenderSetup.RenderSetupBuilder#bufferSize(int)` is removed and `RenderType#bufferSize()` is removed. Use the

**Do: 26.2 form of `CustomRenderType`.** Mirrors vanilla 26.2 `CUTOUT_BLOCK` / `TRANSLUCENT_BLOCK`, which are

```java
package capsule.client.render;

import com.mojang.blaze3d.GpuFormat;
import com.mojang.blaze3d.PrimitiveTopology;
import com.mojang.blaze3d.pipeline.BlendFunction;
import com.mojang.blaze3d.pipeline.ColorTargetState;
import com.mojang.blaze3d.pipeline.DepthStencilState;
import com.mojang.blaze3d.pipeline.RenderPipeline;
import com.mojang.blaze3d.platform.CompareOp;
import com.mojang.blaze3d.systems.RenderSystem;
import com.mojang.blaze3d.textures.AddressMode;
import com.mojang.blaze3d.textures.FilterMode;
import com.mojang.blaze3d.vertex.DefaultVertexFormat;
import net.minecraft.client.renderer.BindGroupLayouts;
import net.minecraft.client.renderer.rendertype.LayeringTransform;
import net.minecraft.client.renderer.rendertype.RenderSetup;
import net.minecraft.client.renderer.rendertype.RenderType;
import net.minecraft.client.renderer.texture.TextureAtlas;
import net.minecraft.resources.Identifier;

import java.util.Optional;

/** Ghost blocks: GHOST_DEPTH keeps the nearest ghost surface per pixel, GHOST then blends only that surface. */
public final class CustomRenderType {
    private CustomRenderType() {}

    private static RenderPipeline.Builder ghostPipeline(String path) {
        return RenderPipeline.builder()
                .withLocation(Identifier.fromNamespaceAndPath("capsule", "pipeline/" + path))
                .withVertexShader("core/block")
                .withFragmentShader("core/block")
                .withBindGroupLayout(BindGroupLayouts.GLOBALS)
                .withBindGroupLayout(BindGroupLayouts.FOG)
                .withBindGroupLayout(BindGroupLayouts.SAMPLER0_SAMPLER2)
                .withBindGroupLayout(BindGroupLayouts.MATRICES_PROJECTION)
                .withVertexBinding(0, DefaultVertexFormat.BLOCK)
                .withPrimitiveTopology(PrimitiveTopology.QUADS)
                .withCull(false);
    }

    // was: cutout shader, DEPTH_WRITE (no color), LEQUAL_DEPTH_TEST -> reverse-Z GREATER_THAN_OR_EQUAL
    public static final RenderPipeline GHOST_DEPTH_PIPELINE = ghostPipeline("ghost_depth")
            .withShaderDefine("ALPHA_CUTOUT", 0.5f)
            .withColorTargetState(new ColorTargetState(Optional.empty(), GpuFormat.RGBA8_UNORM, ColorTargetState.WRITE_NONE))
            .withDepthStencilState(new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, true))
            .build();

    // was: translucent shader, TRANSLUCENT_TRANSPARENCY, COLOR_WRITE (no depth write), LEQUAL -> GREATER_THAN_OR_EQUAL
    public static final RenderPipeline GHOST_PIPELINE = ghostPipeline("ghost")
            .withShaderDefine("ALPHA_CUTOUT", 0.1f)
            .withColorTargetState(new ColorTargetState(BlendFunction.TRANSLUCENT))
            .withDepthStencilState(new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, false))
            .build();

    private static RenderSetup ghostSetup(RenderPipeline pipeline) {
        return RenderSetup.builder(pipeline)
                .useLightmap()
                // mipped block atlas, same sampler as vanilla's moving-block types
                .withTexture("Sampler0", TextureAtlas.LOCATION_BLOCKS, () -> RenderSystem.getSamplerCache()
                        .getSampler(AddressMode.CLAMP_TO_EDGE, AddressMode.CLAMP_TO_EDGE, FilterMode.LINEAR, FilterMode.NEAREST, true))
                .setLayeringTransform(LayeringTransform.VIEW_OFFSET_Z_LAYERING)
                .createRenderSetup();              // no .bufferSize(..) in 26.2
    }

    public static final RenderType GHOST_DEPTH = RenderType.create("capsule:ghost_depth", ghostSetup(GHOST_DEPTH_PIPELINE));
    public static final RenderType GHOST = RenderType.create("capsule:ghost", ghostSetup(GHOST_PIPELINE));
}
```
Notes:
- `CustomRenderType` must no longer `extends RenderType`: the constructor is private in 26.x.
- Register the pipelines on NeoForge with
  `modEventBus.addListener((RegisterRenderPipelinesEvent e) -> { e.registerPipeline(CustomRenderType.GHOST_DEPTH_PIPELINE); e.registerPipeline(CustomRenderType.GHOST_PIPELINE); })`
  (the class exists in NeoForge 26.2.0.95). Fabric compiles unregistered pipelines lazily on first use
  (`GpuDevice#precompilePipeline` exists if you want to warm them up).
- `core/block.vsh` / `.fsh` exist in 26.2 and honour `ALPHA_CUTOUT`.
- In `CapsuleTemplateRenderer.java:54-59`: delete `GHOST_BUFFERS` entirely with path A. With path B, replace it with
  the `StagedVertexBuffer` from §3, sized with `RenderType.BIG_BUFFER_SIZE`.

- **Render Areas** (`CommandEncoder#createRenderPass(..., RenderArea)`): Capsule creates no render passes; path B
  uses `PreparedRenderType#drawFromBuffer`.
- **Font Preparations** (`Font#drawInBatch*` removed): Capsule draws text only through screen/GUI extractor methods.
- **Submitting Gizmos** (`GizmoFeatureRenderer`): emitter API unchanged; only matters if the 26.1 port used Gizmos,
  and then nothing changes.
- **Dispatching Picture-In-Picture**: Capsule has no PiP renderers.
- **Custom feature renderers/phases** (the `SubmitNode`/`FeatureRenderPhase`/`FeatureRenderer` how-to in "Feature
  Rendering"): `submitCustomGeometry`/`submitShapeOutline` suffice; no custom feature type needed.
- **Advancements and Entity Sub Predicates**: no entity predicates in Capsule code or JSON.
- **Tags Provider Changes**: Capsule has no datagen.
- **Sulfur Cube Archetypes**: new content, not used.
- **Shears Breaking Speed**: not used.
- **Structure Processor Unrolling**: Capsule neither implements nor calls `StructureProcessor`s (its
  `processBlockInfos` is its own code). `StructurePlaceSettings` API is unchanged.
- **Game Test Entity Builders**: Capsule's gametests do not call `helper.spawn*`.
- **Xbox Friend List** (`IntegratedServer#publishServer`, `Connection`, ...): not used.
- **Data Component Additions** (`sulfur_cube_content`): not used.
- **Entity Attribute Additions**: not used.
- **Tag Changes** (new vanilla tags; removed `BlockTags` such as `OAK_LOGS`, `SAPLINGS`, ...): none of the removed tags
  are used.
- **List of Additions**: only `PotentSulfurBlockEntity` matters (§13).
- **List of Changes, other entries** (`MobEffect` renames, `LivingEntity` knockback/blocking signatures, `Mob` shear
  methods, `DimensionType#infiniburn`, worldgen/density/surface rules, `PlayerTeam`/`TeamColor`, `LecternBlock#ownSignal`,
  `ChunkAccess#markPosForPostProcessing`, `Mth` axis types, `OptionInstance` listeners, ...): no Capsule usage found.
- **List of Removals, other entries** (sign/bed sheet sprites, `Tuple`, `BlockPos#getCenter`/`getBottomCenter`,
  `I18n#exists`, `Minecraft#isSingleplayer`/`getVersionType`, `Mob#setBodyArmorItem`, ...): no Capsule usage (checked
  by grep).
