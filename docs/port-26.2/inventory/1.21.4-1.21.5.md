Scope: what changes in the NeoForged primers `1.21.4.md` and `1.21.5.md` mean for Capsule (the repository root, branch `1.21.1`).
All paths are relative to the repo root. Line numbers are for the current `1.21.1` sources.
The 1.21.2 changes are covered elsewhere. Where a 1.21.2 change also touches one of these lines, it is mentioned only when 1.21.4/1.21.5 changes the same API again.

Conventions:
- **[LATER]** means a later primer changes this area again (1.21.6+ or 26.x). Do this step in a way that is easy to redo, or merge it with the later step.
- **[VERIFY]** means the exact signature comes from memory or from the primer only. Check it against the decompiled target sources or the loader javadoc before applying it.

# Part 1: 1.21.3 → 1.21.4

- Affected: `common/src/main/resources/pack.mcmeta:3-6` (`pack_format: 34`, `supported_formats 34..48`).

## 1.2 Client Items: `assets/<ns>/items/*.json` is now required for every item

- What changed: how an item renders now comes from a *client item* file at `assets/<namespace>/items/<item path>.json`, with a `model` object (`minecraft:model`, `minecraft:range_dispatch`, `minecraft:select`, `minecraft:condition`, `minecraft:composite`, `minecraft:special`, ...). A model JSON is no longer looked up from the item id. An item without a client item file renders as the missing model.
- Affected: Capsule registers two items and has no `assets/capsule/items/` folder:
  - `capsule:capsule`: `common/src/main/java/capsule/items/CapsuleItems.java:36`
  - `capsule:capsulemarker` (a BlockItem): `common/src/main/java/capsule/blocks/CapsuleBlocks.java:105`
- Instructions:
  1. Create `common/src/main/resources/assets/capsule/items/capsulemarker.json`:
     ```json
     { "model": { "type": "minecraft:model", "model": "capsule:item/capsulemarker" } }
     ```
  2. Create `common/src/main/resources/assets/capsule/items/capsule.json` (see 1.3 and 1.4). It uses a custom range property for the state and a custom tint source for the colors.

## 1.3 Ranged Property Model (`ItemProperties` / model `overrides` → `range_dispatch`)

- What changed: `ItemProperties`, `ItemPropertyFunction` and `ClampedItemPropertyFunction` are removed. So are `BakedOverrides`, `ItemOverride` and the `overrides` list in item model JSON. A numeric property is now a `RangeSelectItemModelProperty`:
  - method: `float get(ItemStack stack, @Nullable ClientLevel level, @Nullable LivingEntity entity, int seed)`
  - method: `MapCodec<? extends RangeSelectItemModelProperty> type()`
  - registration: its `MapCodec` goes into `RangeSelectItemModelProperties.ID_MAPPER`, which is private.
  - use: the client item JSON references it as `"type": "minecraft:range_dispatch", "property": "<id>"`.

  The selected entry is the highest `threshold` that is at or below the value. Below every threshold, `fallback` is used. This matches the old override semantics.

## 1.4 Tint Sources (`ItemColor` → `ItemTintSource`)

- What changed: `ItemColor` and `ItemColors` are removed. Each `tintindex` in a model is now colored by the `tints` list of the `minecraft:model` entry in the client item. Each element of that list is an `ItemTintSource`:
  - method: `int calculate(ItemStack, @Nullable ClientLevel, @Nullable LivingEntity)`, which must return an opaque ARGB value
  - method: `MapCodec<? extends ItemTintSource> type()`
  - registration: its codec goes into `ItemTintSources.ID_MAPPER`, which is private.
  - built-in sources: `minecraft:constant`, `minecraft:dye` (`DYED_COLOR` or a default), and others.
- Affected:
  - `neoforge/src/main/java/capsule/neoforge/CapsuleNeoForgeClient.java:22` (import `RegisterColorHandlersEvent`), `:45-46` (`RegisterColorHandlersEvent.Item` → `event.register(CapsuleItem::getColorFromItemstack, CAPSULE)`).
  - `fabric/src/main/java/capsule/fabric/CapsuleFabricClient.java:16` (import `ColorProviderRegistry`), `:47` (`ColorProviderRegistry.ITEM.register(...)`).
  - `common/src/main/java/capsule/items/CapsuleItem.java:870-894` (`getColorFromItemstack(ItemStack, int renderPass)`). This logic is kept as is and called from the new tint source. Pass 0 is the `DYED_COLOR` rgb (default `0xFFFFFF`). Pass 1 is custom_data `color`, or `0x7CC4EA` for a deployed blueprint. Pass 2 is `0x3BB3FC` for a blueprint, otherwise white. The method already ORs in `0xFF000000`.
  - Item models whose `layer0..2` use tint indices 0..2: `common/src/main/resources/assets/capsule/models/item/capsule*.json` (9 files). They are unchanged, because `item/generated` gives layer N tintindex N.
- Instructions:
  1. New common class `common/src/main/java/capsule/client/render/CapsuleTintSource.java`:
     ```java
     public record CapsuleTintSource(int layer) implements ItemTintSource {
         public static final MapCodec<CapsuleTintSource> MAP_CODEC = RecordCodecBuilder.mapCodec(i -> i.group(
                 Codec.INT.fieldOf("layer").forGetter(CapsuleTintSource::layer)
         ).apply(i, CapsuleTintSource::new));
         @Override
         public int calculate(ItemStack stack, @Nullable ClientLevel level, @Nullable LivingEntity entity) {
             return CapsuleItem.getColorFromItemstack(stack, layer); // already opaque (0xFF000000 | rgb)
         }
         @Override
         public MapCodec<CapsuleTintSource> type() { return MAP_CODEC; }
     }
     ```
     Imports: `net.minecraft.client.color.item.ItemTintSource`.
  2. Register it as `capsule:layer`:
     - NeoForge: `modEventBus.addListener((RegisterColorHandlersEvent.ItemTintSources e) -> e.register(ResourceLocation.fromNamespaceAndPath(CapsuleMod.MODID, "layer"), CapsuleTintSource.MAP_CODEC));` **[VERIFY]** event name.
     - Fabric: add an access widener entry `accessible field net/minecraft/client/color/item/ItemTintSources ID_MAPPER Lnet/minecraft/util/ExtraCodecs$LateBoundIdMapper;`. Then call `ItemTintSources.ID_MAPPER.put(id, CapsuleTintSource.MAP_CODEC)` in `onInitializeClient()`.
  3. The tints list `T` used in 1.3:
     ```json
     [ { "type": "capsule:layer", "layer": 0 }, { "type": "capsule:layer", "layer": 1 }, { "type": "capsule:layer", "layer": 2 } ]
     ```
     Optionally, entry 0 could be `{ "type": "minecraft:dye", "default": 16777215 }`. That is identical to pass 0, but the custom source keeps all the logic in one place.
  4. Delete the `ItemColor` registrations listed above. Also remove the comment at `CapsuleItem.java:892` ("NeoForge 1.21.1 interprets color as ARGB"); the opaque rule now applies to all tint sources.
